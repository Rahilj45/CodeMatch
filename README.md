> **Core Objective:** Recommend the right problem to the right programmer at the right time.

CodeMatch is an intelligent, full-stack competitive-programming recommendation platform. It analyzes a programmer's Codeforces profile, submission history, solved vs attempted problems, ratings, and tags to detect topic strengths and weaknesses—then deterministically recommends the optimal next problems to advance their rating.

---

## 🌟 Key Features

1. **Official Codeforces Ingestion Engine:**
   - Synchronizes profile metadata, ratings, historical submissions, execution times, and problem tags for handle `Rahilj45`.
   - Ingests 11,500+ problems from the official Codeforces catalogue.
   - Built-in rate limiting (0.35s request interval) and exponential backoff retry.
   - Strict duplicate prevention on `submission_id` and unique problem keys (`contestId:index`).

2. **Mathematical Skill Analysis:**
   - Evaluates topic-level performance using Bayesian Laplace smoothing:
     $$\text{Smoothed Accuracy} = \frac{N_{\text{solved}} + 2}{N_{\text{attempted}} + 4}$$
   - Categorizes skills cleanly into **Strong** ($\ge 70\%$), **Developing** ($40\% - 70\%$), **Weak** ($< 40\%$), or **Insufficient Data** ($< 4$ attempts).
   - Generates difficulty distributions and verdict breakdowns (Accepted vs WA vs TLE).

3. **Deterministic Hybrid Recommendation Engine:**
   - **Gaussian Difficulty Matching ($35\%$):** Centers recommendations around the user's optimal growth zone ($R_{\text{user}} + 75$ rating) using a normal decay curve ($\sigma = 180$).
   - **Topic Weakness Remediation ($30\%$):** Prioritizes topics with demonstrated failure rates.
   - **Semantic Similarity ($20\%$):** Matches problem concepts using 384-dimensional dense vectors generated by `sentence-transformers/all-MiniLM-L6-v2` and cosine similarity.
   - **Community Quality ($15\%$):** Favors well-tested, vetted problems with high solved counts.
   - **Redemption Opportunities ($+8\%$):** Identifies previously attempted but unsolved problems for mastery reinforcement.
   - **Topic Diversity Filter:** Prevents single-topic clustering across the recommended set.
   - **Strict Solved Problem Exclusion:** Solved problems are never re-recommended.

4. **Transparent Recommendation Explanations:**
   - Every problem recommendation explains **why** it was chosen, which weakness it targets, and why the rating is appropriate for the user.

5. **Modern Dark-First SaaS Interface:**
   - Deep navy and charcoal background (`#0B0F17`, `#111827`) with subtle indigo/purple accents.
   - 8 fully functional views: **Landing**, **Authentication**, **Onboarding**, **Dashboard**, **Recommendations**, **Analytics**, **Profile**, **Settings**.
   - Interactive charts built with **Recharts**.
   - Save, Skip, and Mark-as-Solved feedback actions.

## ⚡ Quick Start (Local Development)

### 1. Prerequisites
- Python 3.11 or higher
- Node.js 18+ & npm
- Git

### 2. Clone Repository
```bash
git clone https://github.com/Rahilj45/CodeMatch.git
cd CodeMatch
```

### 3. Backend Setup
```bash
cd backend

# Install dependencies
pip install -r requirements.txt

# Run automated tests
pytest tests/ -v

# Start FastAPI server
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
API runs at: `http://localhost:8000`  
Interactive OpenAPI Docs: `http://localhost:8000/api/docs`

### 4. Frontend Setup
In a new terminal:
```bash
cd frontend

# Install dependencies
npm install

# Start Vite development server
npm run dev
```
Web application opens at: `http://localhost:5173`

## 🐳 Docker Deployment

To launch the complete platform (PostgreSQL with `pgvector`, FastAPI backend, and Nginx-served React frontend) in a single command:

```bash
docker-compose up --build
```

- **Frontend:** `http://localhost:5173`
- **Backend API:** `http://localhost:8000`
- **PostgreSQL:** `localhost:5432`

## ☁️ Production Deployment

### 1. Database (Supabase)
1. Create a Supabase project at [supabase.com](https://supabase.com).
2. Run the migration file `supabase/migrations/20261124_000001_initial_schema.sql` in the Supabase SQL Editor.
3. Retrieve your project's `DATABASE_URL` and service role key.

### 2. Backend (Render)
1. Connect your GitHub repository to [Render](https://render.com).
2. Create a new **Web Service** using the root `render.yaml` or Dockerfile in `backend/`.
3. Set the environment variable `DATABASE_URL` to your Supabase connection string.

### 3. Frontend (Vercel)
1. Import the repository on [Vercel](https://vercel.com).
2. Set root directory to `frontend`.
3. Configure `vercel.json` rewrites to forward `/api` requests to your Render backend.

## 🔒 Security & Privacy

- **Row Level Security (RLS)** is enabled on all user-sensitive tables.
- Public read access is strictly limited to problems and embeddings.
- No database credentials or secrets are baked into client-side code.
- Inputs are validated using Pydantic schemas.
